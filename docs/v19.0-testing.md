# Matomo 19.0 testing

## Scope and source decision

Debian 13 Trixie does not package the Matomo server. The appliance installs
the current supported Matomo 5.13.0 archive from the official GitHub release
and verifies the SHA-256 digest published in that release's metadata. PHP 8.4,
MariaDB, Apache, Postfix, Adminer and Webmin come from the signed Debian Trixie
and TurnKey repositories.

## Acceptance command

```sh
/sandboxed-git/turnkey/tools/test-v19-appliance matomo \
    --source /home/agent/.local/worktrees/turnkey-apps/matomo/wish-matomo-v19-trixie
```

## Supervised Matomo updates

Back up the appliance and database before updating. Download the next stable
archive from the official Matomo GitHub releases and verify the digest
published with that release. Replace the application files while preserving
`/var/www/matomo/config/config.ini.php`, restore ownership to `www-data`, then
run `sudo -u www-data php console core:update --yes` from
`/var/www/matomo`. Review upstream release and upgrade notes before crossing a
major release line.

Debian components continue to receive normal APT maintenance from the signed
Trixie and TurnKey repositories.

## Economical preflight evidence

A disposable Debian Trixie container installed Matomo 5.13.0 on PHP 8.4,
MariaDB and Apache from the official archive. It verified the published digest,
completed the current web installer, applied the same firstboot password hash,
authenticated through the real administrator login, submitted a tracking
event, ran the Matomo archiver and confirmed the resulting analytics record.
The preflight also showed that the old installer `trackingCode` action now
returns HTTP 500, so the v19 build proceeds directly from website creation to
the supported completion action.

## Known limitation

The disposable container does not exercise appliance boot or firstboot service
ordering. The exact appliance acceptance command covers those paths. The Core
19 baseline supplies inherited ISO, bootloader and hardware-boundary evidence.
