# Matomo 19.0 testing

## Scope and source decision

The appliance installs Matomo and its PHP dependencies from Debian 13
Trixie's signed package repository. MariaDB, Apache, Postfix, Adminer and
Webmin also come from the signed Debian Trixie and TurnKey repositories.
Trixie does not package the optional GeoIP2 PHP API required by Matomo's
geographic reports, so Composer installs its locked upstream release.

## Acceptance command

```sh
/sandboxed-git/turnkey/tools/test-v19-appliance matomo \
    --source /home/agent/.local/worktrees/turnkey-apps/matomo/fix-matomo-v19-report-visibility
```

## Supervised Matomo updates

Back up the appliance and database before updating. Refresh the signed package
metadata and run `apt-get install matomo`. Review the Debian package changelog
and Matomo upgrade notes before applying a major release transition. Review
the GeoIP2 PHP API release notes, then run `COMPOSER_ALLOW_SUPERUSER=1 composer update
--working-dir=/usr/local/share/matomo-geoip2 geoip2/geoip2
--with-all-dependencies` to update that optional upstream component and its
locked dependencies.

## Economical preflight evidence

A disposable Debian Trixie package inspection confirmed that Matomo
`5.3.1+dfsg-1` and its runtime dependencies resolve from the signed stable
repository. This establishes package availability and layout only. Exact
appliance results are recorded below.

A focused Trixie container installed the locked GeoIP2 PHP API, resolved a
real address from the downloaded DB-IP Lite database, and ran the configured
Matomo archiver with the `geoip2php` provider active. The complete secret hook
then rotated the Matomo salt and database password, left `core:version`
healthy, and produced an empty archive error log. A Composer dry-run found no
dependency changes and its locked-package audit found no security advisories.

## Known limitation

Disposable containers and the exact Docker path do not exercise ISO,
bootloader or hardware behavior. The Core 19 baseline supplies that inherited
evidence.
